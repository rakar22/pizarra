# Auditoría técnica de Pizarra — 2026-09-17

## Resumen ejecutivo

La versión actual de Pizarra tiene una base técnica sólida para una mesa de análisis: TanStack Start/Router, React 19, React Query, TypeScript, fuentes de fútbol separadas, modelos de análisis, Scout y una UI orientada a iOS. El principal problema funcional detectado en la sección **Ligas** era el camino de carga de detalle: al abrir una liga se reutilizaba `getBoard()`, que recalculaba/cargaba el tablero completo antes de mostrar el detalle.

### Incidencia prioritaria

**Síntoma:** al tocar una liga, la navegación podía parecer que no hacía nada.

**Causa técnica:** `/ligas/$slug` dependía de `getLeague()`, y `getLeague()` llamaba a `loadBoard()`. `loadBoard()` consulta tablas de muchas competiciones, varios headers de ESPN, OpenLigaDB y después el overlay de cuotas. En un proceso frío o con fuentes lentas, la navegación quedaba esperando una operación mucho más grande de la necesaria.

**Corrección aplicada:** el detalle de liga usa ahora `getLeagueFast()`, que consulta únicamente la competición seleccionada, mantiene una caché específica por liga y tiene fallback de OpenLigaDB para Bundesliga. Además, los enlaces usan preload por intención y la ruta tiene estado pending visible y recuperación ante error.

## Pros

- Arquitectura moderna basada en TanStack Start/Router y React.
- Separación razonable entre UI, fuentes, parsing, modelos y lógica de servidor.
- Registro centralizado de ligas en `src/lib/football/leagues.ts`.
- Modelado de partidos y clasificación preparado para incorporar más fuentes.
- Uso de caché para reducir llamadas repetidas a proveedores externos.
- Scout IA aislado detrás de una server function y sin exponer la clave de xAI al cliente.
- El producto diferencia análisis de ejecución automática de apuestas.
- La UI white/iOS es consistente y responsive.
- CI existente y ahora ampliada para typecheck, tests, lint y build.

## Contras / deuda técnica

### Alta prioridad

1. **Dependencia fuerte de fuentes externas en tiempo real.** ESPN/OpenLigaDB pueden fallar o cambiar payloads. El parser tiene tolerancia, pero faltan contratos de integración ejecutados periódicamente.
2. **Tablero global costoso.** `getBoard()` sigue siendo una operación grande; debe mantenerse cacheada y, a medio plazo, alimentarse desde un job persistente en lugar de depender de cada request web.
3. **Cuotas.** Las cuotas y sus fuentes deben mostrar siempre timestamp, proveedor y estado de frescura. Nunca deben presentarse como cuotas actuales si proceden de una captura/cache antigua.
4. **Observabilidad.** Falta instrumentación estructurada de latencia, errores por proveedor, ratio de respuestas vacías y edad de caché.

### Prioridad media

5. **Histórico persistente.** El proyecto necesita almacenamiento histórico para backtesting real y comparación temporal de modelos.
6. **Calibración.** Brier/Log Loss/calibración deben alimentarse con un dataset out-of-sample persistente y no solo con cálculos bajo demanda.
7. **Modelo.** Poisson es una buena base, pero la siguiente evolución debe comparar modelos fuera de muestra antes de sustituirlo.
8. **Testing E2E.** Falta una prueba Playwright que abra `/ligas`, toque una liga y compruebe que cambia a `/ligas/$slug` y que aparece la tabla o el estado de datos.
9. **Accesibilidad.** Hay que seguir auditando foco, contraste, labels y navegación por teclado.

### Prioridad baja

10. Reducir duplicación entre carga del tablero y carga de competición mediante una capa de repositorio de datos compartida.
11. Añadir estados de freshness y source badges en las pantallas de datos.
12. Añadir tests de parsers para payloads reales anonimizados de ESPN/OpenLigaDB.

## Cambios aplicados en esta auditoría

- Nuevo loader específico `getLeagueFast()` para no recalcular todo el tablero al abrir una liga.
- Caché independiente de 120 segundos por liga.
- Fallback de Bundesliga mediante OpenLigaDB cuando ESPN no devuelve partidos.
- Preloading por intención en enlaces de liga.
- Preloading global de navegación TanStack Router.
- Estado visual de carga de la ruta de liga.
- Estado de error con botón **Reintentar**.
- Estado explícito cuando una liga no tiene datos disponibles.
- Timeout de 10 segundos para peticiones externas de fútbol, manteniendo reintentos.
- Test del registro de ligas y de sus identificadores ESPN.
- CI ampliada para `typecheck`, `test`, `lint` y `build`.

## Próximas mejoras recomendadas

1. Añadir E2E con Playwright para navegación de Ligas y Partidos.
2. Crear un job de ingestión histórico con idempotencia.
3. Persistir snapshots de standings, fixtures y odds con timestamp.
4. Añadir health checks por proveedor.
5. Separar definitivamente ingestion, cache y presentación.
6. Construir un pipeline de backtesting reproducible con ventanas temporales y evaluación out-of-sample.
7. Añadir observabilidad de producción antes de escalar fuentes o mercados.
